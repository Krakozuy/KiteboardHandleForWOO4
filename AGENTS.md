# Правила работы с KiteHandleWoo

- После каждого законченного изменения проекта создавай локальный Git-коммит с понятным описанием. Не оставляй собственные завершённые изменения незакоммиченными.
- При каждом обновлении скрипта повышай версию и синхронизируй её в Python, manifest и README. Изменения только служебных файлов Git не требуют новой версии скрипта.
- Не запускай и не тестируй скрипт, включая запуск в Fusion, без нового явного разрешения пользователя.
- Сохраняй настраиваемые параметры в начале Python-файла; комментарии и пояснения пиши по-русски.
- Основные исходники: outputs/KiteHandleWoo/KiteHandleWoo.py, KiteHandleWoo.manifest и README.txt.
- После обновления выпуска пересобирай outputs/KiteHandleWoo.zip из этих трёх файлов. Генерируемые модели, отчёты, архивы и work не включай в Git.
- Историю версий храни в Git. Не переписывай существующие коммиты и не вставляй полный журнал Git внутрь Python-файла.
- Для новых выпусков создавай тег v<версия>. Не перемещай существующие теги.
- Не публикуй репозиторий и не отправляй коммиты на удалённый сервер без запроса пользователя.
